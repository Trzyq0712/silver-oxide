# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**silver-oxide** is a Rust implementation of a high-performance verification backend for [Silver/Viper](https://github.com/viperproject/silver), developed at ETH Zürich (Programming Methodology Group, supervisor: Jonas Fiala).

The project has two layers:

1. **Parser & translator**: parses Silver programs, builds an AST, and lowers them to VMIR (Viper Mid-level IR).
2. **Verification backend**: verifies VMIR using equality reasoning via the [`egg`](https://egraphs-good.github.io/) e-graph library, with Z3 as a fallback for obligations that exceed equality saturation.

The core research hypothesis is that *most* proof obligations generated by [Prusti](https://github.com/viperproject/prusti-dev) for unannotated Rust programs — particularly those involving struct manipulation — can be discharged via lightweight equality reasoning rather than full SMT solving, yielding significant performance improvements over Silicon.

Requires nightly Rust (`rust-toolchain.toml` pins `channel = "nightly"`).

## Architecture: Silver → VMIR → Verification

The pipeline lives across three top-level modules, mirrored in `src/`:

### 1. `src/viper/` — Parsing, AST & Type Checking

- `parser.rs`: PEG parser (`viper_parser::vpr_program(input)`) using the `peg` crate. Prioritizes legibility over performance.
- `parsed/`: the parsed (untyped) Silver AST, re-exported as `viper::parsed::*`. `ast_ext.rs` adds helper impls; `builtins.rs` holds built-in declarations.
- `typed/`: the typed AST produced by type checking (`ast.rs`), plus `Display`/`Show` rendering (`display.rs`). This is what translation consumes.
- `globals.rs`: `Globals` / `GlobalsCollector` — catalog of all top-level declarations.
- `interner.rs`: `Interner` / `IdentCollector` — identifier interning.
- `typecheck/`: Silver-level type checking — `typecheck_program` (entry), `TypeError`, plus the type `lattice.rs`.
- `walk.rs`: AST traversal trait.

### 2. `src/translate/` — Silver → VMIR Translation

Entry point: the free function `translate::translate(...)` in `mod.rs`, which consumes the **typed** AST (`viper::typed`) plus `Globals`/`Interner` and emits a `vmir::Program`. Type checking is done upstream in `src/viper/typecheck/`; do **not** add type-checking logic here.

Sub-modules:
- `method.rs`: lowers method bodies (statements, assignments, method-call inhale/exhale).
- `resource.rs`: lowers contracts (`requires`/`ensures`) and concrete predicate bodies into `vmir::Resource` declarations (named `method#requires` / `method#ensures`, predicate name for predicates). `lower_spatial_never` lowers a spatial assertion into a guarded inst stream + result tuple.
- `pure_exp.rs`: pure-expression lowering helpers.
- `errors.rs`: `TranslationError`.

### 3. `src/vmir/` — VMIR IR

`vmir::Program` holds a `TiVec<MemberId, Declaration>` and a `lasso::Rodeo<MemberId>` interner. Declarations:
- `Function` — Silver functions and predicates (and fields modeled as `Ref → Addr<T>`)
- `Resource` — reusable unit of proof. `body: Option<ResourceBody>` — `None` for **abstract** resources (e.g. abstract predicates), `Some(_)` for concrete ones. A `ResourceBody` is a list of guarded `Inst` + a result tuple `(HeapVal, Val)` (heap delta + boolean condition). Inhale = add delta + assume bool; exhale = subtract delta + assert bool. Params occupy `Val::Temp(0..n_params)`; body heaps count from `HeapVal::Temp(0)` — there is no reserved ctx-heap slot. A **two-state** resource (`Precond::Ctx`, i.e. `m#ensures` when `m` has a `requires`) receives its pre-state as a trailing **snapshot parameter** `s : Snap(req_id)` and opens with `HeapInst::FromSnap { resource: req, args, snap: s }` reconstructing the pre-state heap (`h0`) that `old(...)` reads — the same mechanism as heap-dependent functions. An `Inhale`/`Exhale` of a **self-framed** resource additionally yields the snapshot of the in/ex-haled resource as a pure `Val` (`h1, e5 := h0 inhale R(...) 1/1`; derived via `HeapInst::snap_yield`, bumps the `Val` counter); that snapshot is what call sites pass as the two-state resource's trailing arg (`m#requires`'s snapshot feeds `m#ensures`). **Calling an abstract resource via `ResourceCall` is illegal** — the frontend uses the resource's auto-emitted `@addr` function for `acc(R(args), perm)` instead.
- `Method` — method bodies emitted for methods that have a Silver body. A method call inside a body lowers to: exhale `m#requires(args)` (asserts the requires bool, yields the pre-state snapshot `s`); fresh return allocations; inhale `m#ensures(args ++ rets ++ [s])` (assumes the ensures bool). A method's own body inhales `m#requires(params)` at entry (yielding `s`) and exhales `m#ensures(params ++ rets ++ [s])` at each exit.
- `Domain`, `Adt`, `DomainElement`, `AdtConstructor` — domain/ADT stubs.

Every instruction is `Inst { pc: PathCond, kind: InstKind }`. The path condition is a list of `Lit { val: Val, polarity: bool }` over previously-emitted `Val`s, rendered `<e1, !e3, e5>` (polarity `false` prints as `!`). It constrains when side conditions of `kind` must hold (e.g., `acc` requires `perm ≥ 0`, `div` requires non-zero divisor) and gates any knowledge produced (e.g., chunk-merge equalities from heap union). Empty `<>` is the trivial guard. `InstKind` is one of:
- `Pure(Type, PureInst)` — produces a `Val::Temp`. Variants: `Fresh`, `Binary(op, a, b)`, `Ternary(c, t, e)`, `Deref(heap, addr)`, `Perm(heap, addr)`, `FunctionCall`, `Snap { resource, args, heap }` (heap-dep call site: narrow the current heap to the callee's precondition snapshot, implicitly asserting footprint sufficiency + the resource bool). Field/predicate `addr` functions are ordinary uninterpreted `FunctionCall`s.
- `Heap(HeapInst)` — produces a `HeapVal::Temp`. Variants: `Combine { base, sign, loc, perm }` (add/subtract one location chunk; `sign` is `Add`/`Sub`), `Inhale`/`Exhale { base, call, perm }` (add/subtract a resource delta **and** assume/assert its bool; a self-framed callee additionally yields a snapshot `Val` — see `HeapInst::snap_yield`), `Assign(base, { loc, val })`, `Fold`/`Unfold { base, call, perm }`, `FromSnap { resource, args, snap }` (widen a snapshot back into a heap). `Combine` with `Sign::Sub` is **method-body only** — illegal in resource bodies (`declaration.rs` rejects it). **There is no `HeapInst::Ternary`**: control flow lowers to a single *linear reach-gated* heap thread (`current_heap` threaded in topo order, off-path perms gated to 0 via `Sink::gate_perm`), not a per-branch heap phi. Re-adding a heap ternary for a *select*-shaped join — so a per-arm-constructed permission collapses to `1/1` by local rewrites instead of the additive `Σ ite` that only `merge_ite_sum` cracks — is an open retrofit (see `presentation/why_switch_architecture.typ`).
- `ResourceCall { resource, args }` — produces a **pair** `(HeapVal::Temp, Val::Temp)`: the called resource's `(delta, bool)`. Both temp counters bump. Target resource must have `body: Some(_)`. Abstract resources are uncallable.
- `Assume(Val)` / `Assert(Val)` — boolean side checks. Produce no temps. Rendered without `:=` (e.g. `<pc> assert eN`). Emitted in method bodies **and function bodies**, and wherever a contract-bearing function is applied. **Function calls are always pure and heap-free** — no ctx heap, no pre/postcondition builtin. A **heap-free** function's contracts are ordinary boolean functions (`f#requires : params → Bool`, `f#ensures : params ++ result → Bool`) recorded both in the frontend `contracts` map and as **contract links on the `Function` decl** (`requires: Option<Requires>`, `ensures: Option<ContractCall<ContractArg>>`; `ContractArg::Result` — the function's result — is expressible only in the ensures link). `Requires` is the one place the two function flavours diverge: `Requires::Pure(ContractCall<Val>)` (heap-free — a boolean function) vs `Requires::Framed { resource, args, snap }` (heap-dependent — a self-framed Resource plus the trailing snapshot param), so "heap-dep ⟺ `#requires` is a Resource ⟺ there is a trailing `Snap` param" holds by construction. Stitching: the body **assumes** `f#requires(params)` at entry and **asserts** `f#ensures(params, body_result)` at exit; the generated `f#ensures` decl's own body opens with the same entry assume (post WD may rely on the pre) and links back to `f#requires`. A call site **asserts** `f#requires(args)` before the call and nothing after — postconditions are delivered by the verifier as **guarded rewrites keyed on the function symbol**: every body `Assert` (proven under `pre ∧ pc`) is exported as a fact `f#requires(params) ∧ pc ⟹ φ` in the `FunctionDefinition` and replayed at each `f(args)` occurrence (`verify/cert.rs::Fact`, `rewrite.rs::replay_facts`), so transitive call sites learn callee contracts too; an abstract function gets a synthesized post axiom from its links alone. Facts install only if the function verified (success gating); a recursive function's post fact is keyed on the limited twin `f'` as well, and is available during its own body check (induction). A **heap-dependent** function exports facts the same way, guarded by an opaque **pre-token** instead (see below). These are the only way `Assume`/`Assert` reach a resource body — as the by-product of a called function's contract; a resource's own result logic still may not use them.

**Heap-dependent functions** (an `acc` in `requires`) use **snapshot passing** — same `Function` decl, no extra kind. `f#requires` lowers to a **self-framed `Resource`** (footprint + bool; the pure conjuncts live in the resource bool). The function gains a trailing parameter `s : Type::Snap(req_id)`; its body opens with `HeapInst::FromSnap { resource, args, snap }` → a heap holding one chunk per footprint slot valued `unwrap(proj_k(s))`, **implicitly assuming** the resource bool (no boolean entry stitch), and derefs that heap. `f#ensures` is a boolean function `(params ++ [result, s]) → Bool` with the same `FromSnap` entry (postconditions may read the heap). A call site emits `PureInst::Snap { resource, args, heap }` — narrowing the current heap to the snapshot (`present ? Some(v) : None` per slot) while **implicitly asserting** the precondition: footprint sufficiency (exhale-shaped, non-consuming; fractional, same as a method exhale) plus the resource bool — then calls `f(args ++ [s])` like any pure function (no use-site ensures assume). Verification purifies the body against `H(s)` (`verify_function` + `eval_snap`/`eval_from_snap` in `verify/declaration.rs`); `FunctionCertificate` grafting is unchanged since the snapshot is an ordinary param.

**Heap-dep contracts** (postconditions) are delivered by the same guarded-facts machinery, guarded by an **opaque pre-token** `R#pre(args ++ [s]) : Bool` — one uninterpreted symbol per `#requires` Resource (`FuncRegistry::pre_token`), Silicon's `f%precondition`. Unlike a heap-free `f#requires`, the token is *never defined*: "the precondition holds" is not a function of `(args, s)` — it also demands the footprint, which the snapshot's values do not record. It is **stamped** where a `Snap`'s implicit check passed (`eval_snap` assumes `pc ⟹ R#pre(args, s)`), which is what makes the facts it guards sound. The body's exit `assert f#ensures(params, result, s)` is emitted, so concrete heap-dep functions check their own post; a nested heap-dep call's `Snap` additionally exports `outer-token ∧ pc ⟹ R#pre(inner args, s')` (Silicon's `bodyPreconditionPropagationAxiom`), so a transitive caller who rebuilds the recipe can discharge the inner callee's guard without re-running its check. **Known limitation — guarded facts do not cross a branch.** A fact whose guard is only true under a path condition cannot discharge a goal needed at a weaker pc: the e-graph does not case-split, so `!c ⟹ guard ⟹ φ` never collapses `ite(c, φ, …)`. This is **general to guarded fact replay, not heap-dep-specific** — a heap-free callee whose precondition is only provable under the branch fails identically (`e2e::heap_free_post_under_a_branch_hits_the_same_limitation`). The difference is the escape hatch: a heap-free guard is a *defined* formula, so it can be re-derived unconditionally when the context allows (e.g. a domain axiom yields it — which is why `recursive_function_postcondition_by_induction` works); an *opaque* token can never be re-derived, so a heap-dep call under a branch is **always** pc-bound. Recursion itself is fine — a branchless recursive heap-dep function verifies by induction (`e2e::branchless_recursive_heap_dep_function_verifies_by_induction`) — but the usual base-case/recursive-case shape is out. Pinned with the two ways out in `e2e::heap_dep_post_under_a_branch_is_a_known_limitation`.

Instructions are SSA; an instruction has no explicit id. The `Val::Temp` / `HeapVal::Temp` indices are the running counters of `Pure`/`Heap` and `ResourceCall` outputs in the surrounding instruction stream (the two counters are independent).

### 4. `src/verify/` — Verification Backend

Entry: `verify::verify(analyzed: &vmir::AnalyzedProgram)`. Walks the declarations in dependency (topo) order: each `Declaration::Resource` is verified self-contained by `method::verify_resource` (well-formedness side conditions), producing a cached `ResourceCertificate`; each `Declaration::Method` is then verified by `method::verify_method`, grafting the cached certificates at call sites instead of re-walking resource bodies.

The reasoning engine is the [`egg`](https://egraphs-good.github.io/) e-graph. `verify/context.rs` holds the `VerifyContext` (live `EGraph<Symbolic, ConstFold>`, rewrite rules, certificate graft/`transplant`); `verify/lang.rs` defines the type-free `Symbolic` language; `verify/analysis.rs` the `ConstFold` analysis; `verify/rewrite.rs` the rewrite rules; `verify/heap.rs` the symbolic `Heap`/`Chunk`; `verify/viz.rs` the optional Graphviz e-graph snapshots (`SILVER_OXIDE_VIZ`).

**Z3 fallback** (planned, not yet wired): the `z3` crate is present and exercised only by the `z3probe` bin. The verification path is currently egg-only. Z3 is intended as the fallback for non-linear arithmetic and complex functional specs once equality saturation can no longer discharge an obligation.

## Verification Architecture

The pipeline is **Smart Frontend / Dumb IR**: the lowering pass does the heavy structural work (symbolic execution, permission tracking, heap routing) so the solver and the e-graph only have to discharge pure mathematical facts. VMIR is **SSA** and topologically sorted; an instruction's id is implicit — it is the instruction's position in the owning `Vec<Inst>`.

### 1. Syntactic heap framing (no SMT required)

The frontend maintains a symbolic state tracker — a `HashSet` of currently-available resource instances. Framing reduces to a **syntactic equality** check: at a use site requiring `r1(e0)`, the frontend looks for `r1(e0)` in the current state. If present, it emits the IR; if not, it raises a compile error. The SMT solver never sees a framing assertion.

### 2. Pure logic decoupled from heap state

- **No method declarations in VMIR (for now).** A method call is lowered by the frontend into an inhale of the callee's `#requires` resource followed by an exhale of its `#ensures` resource.
- **Heaps are reusable, not linear.** A `HeapVal` is a value, not a consumable token: a pure function or resource accessor may read the same heap any number of times. "Producing a new heap" only happens when an operation actually changes the heap (e.g. `acc`, `Add`, `Ternary`).
- **Booleans flow globally.** The boolean component of a resource is handled via global `Assert`/`Assume` at inhale/exhale sites; the IR only routes heaps locally.

### 3. Explicit path conditions (stateless IR)

VMIR has no stateful `Push`/`Pop` instructions. Every `Inst` is self-contained and carries its own `PathCond` — the exact conjunction of boolean literals required to reach it. This preserves pure data-dependency and makes the IR trivial to analyse, debug, and reorder. (Implementation: `src/vmir/resource.rs` — `Inst { pc: PathCond, kind: InstKind }`, `PathCond { lits: Vec<Lit> }`, `Lit { val: Val, polarity: bool }`.)

### Anatomy of an instruction

```rust
Inst {
    // id implicit — the instruction's index in its owning Vec<Inst>
    pc: PathCond,    // pc literals needed to reach this inst
    kind: InstKind,  // Pure(Type, PureInst) | Heap(HeapInst) | ResourceCall(_)
}
```

How the verifier drives the e-graph (push/pop strategies, ITE handling, goal destructuring) is intentionally not specified here; it will be settled as the backend lands.

## VMIR Design Goals

VMIR is the project's core contribution: a lower-level IR that decomposes Silver into explicit, minimal verification primitives ("verification machine code"). Key design principles:

- **Explicit permissions**: every heap access states its permission amount; no implicit `acc(x.f)` shorthands.
- **Desugared operators**: redundant logical/arithmetic operators are reduced to a core set (e.g. `p <==> q` → `p == q`, `p || q` → `p ? true : q`) to keep the equality engine's rewrite rule set small.
- **Fold/unfold as first-class instructions**: fold and unfold are preserved as explicit VMIR instructions. Desugaring them into inhale/exhale sequences proved too difficult to do soundly, so the backend reasons about them directly.
- **Explicit heap states**: every heap-modifying operation produces a new `HeapVal`; the `old` operator is eliminated by threading the appropriate heap state explicitly. Heaps themselves are reusable values, not linear tokens (Pillar 2).
- **Unified resources**: fields and predicates are both modeled as resources. Their associated snapshot ADT and address function are not emitted explicitly — `resource@addr` is an ordinary `PureInst::FunctionCall`; `resource@snap` is `PureInst::Deref` applied to that result. Method contracts (`requires`/`ensures`) are resources in the same sense.
- **Proof reuse**: resource well-formedness is established once and reused across call sites, avoiding the "copy-paste" redundancy of Silicon.

## Equality Reasoning & `egg`

The verification backend uses [`egg`](https://egraphs-good.github.io/) for equality saturation:

- Verification conditions are encoded as e-nodes; obligations are discharged by checking whether a conjecture and known facts land in the same e-class.
- Congruence closure is used to handle heap consolidation: when `x == y` is learned, `x.f` and `y.f` unify automatically, reducing permission merging from O(n³) to near-linear.
- Rewrite rules encode domain-specific identities (e.g. permission arithmetic, predicate fold/unfold equivalences).
- Quantifier instantiation (e-matching lifted out of Z3 into `egg`) is a stretch goal.

When equality saturation cannot discharge an obligation, the backend falls back to Z3. A key evaluation metric is how much overhead the `egg` pass adds in such fallback cases.

## Key Conventions

- **String interning**: all identifiers go through `lasso::Rodeo<MemberId>`; use `interner.get(name)` to look up an existing `MemberId`, `interner.resolve(&id)` to get the string back.
- **Type-safe indices**: `TiVec<MemberId, T>` — never index with a plain `usize`.
- **`derive_more`**: most AST/IR nodes derive `Display`/`From`/`Into` via this crate.
- **Nightly feature**: `#![feature(never_type)]` is used in `lib.rs`.
- **Resource naming**: method contract resources are interned as `"methodname#requires"` / `"methodname#ensures"`.
- **Resource accessors**: snapshot ADTs and address functions are not emitted as explicit declarations. `resource@addr` is an ordinary uninterpreted `PureInst::FunctionCall` (the field/predicate name resolves to a function returning `Addr<T>`); `resource@snap` is `PureInst::Deref(heap, addr)` applied to that result.
- **Implicit SSA id**: an instruction has no explicit id. A `Val::Temp(n)` / `HeapVal::Temp(n)` refers to the `n`-th `Val` / `HeapVal` produced by the surrounding instruction stream — counters are independent. `Pure` and `ResourceCall` bump the `Val` counter; `Heap` and `ResourceCall` bump the `HeapVal` counter; `Assume`/`Assert` bump neither.
- **Auto-emitted `@addr` and `@snap`**: the translator emits a `Declaration::Function` for every field and predicate address function, and a `Declaration::Domain` interned as `"P@snap"` for every predicate (the opaque snapshot type). A **field**'s address function is interned under the field's **bare name** (e.g. `f`) — `@`-suffixes are reserved for *generated* implicit members; a **predicate**'s address function is interned as `"P@addr"`. `acc(R(args), perm)` lowers to a `PureInst::FunctionCall` to that address function followed by a `HeapInst::Combine` (`Sign::Add`) on the resulting `Addr<…>`.

## Current State & Roadmap

### Done (Phase 1)
Pre-processing passes (parsing, macro inlining, Silver-level type checking, global resolution) and a typed AST (`viper::typed`). SSA-based method lowering; abstract predicates & fields; method-call inhale/exhale lowering. The egg backend verifies small programs end-to-end: resource well-formedness is proven once into a `ResourceCertificate` and grafted (proven e-class merges transferred, no re-saturation) at call sites.

### Done (Phase 2–3, partial)
Predicates with bodies + fold/unfold (`HeapInst::Fold`/`Unfold`, snapshot ADTs, `proj∘cons` round-trips). Function support: heap-free functions (boolean contract fns, defining-equation cert graft, guarded post facts incl. recursion by induction) and **heap-dependent functions** via snapshot passing (`PureInst::Snap` / `HeapInst::FromSnap`, `f#requires` as a self-framed Resource; see the VMIR section), including their postconditions via the opaque pre-token. `cases/heap_functions.vpr` verifies end-to-end.

### In Progress (Phase 3)
Conditional control flow (DAG CFGs) is lowered (goto/join linearization). Remaining work:

- **The permission partition — the enum-match ceiling.** An N-arm `match` reaches its exit exhale with a per-arm-*constructed* resource (e.g. Prusti's `p_0_Tuple`) held as an additive sum `Σ ite(flag_k, 1, 0)`, which equals `1/1` only by "exactly one flag set". No local rewrite reaches it (`add-sub-cancel` needs a matching subtraction; the ite-sum law needs AC matching egg lacks), so it is collapsed today **only** by the `merge_ite_sum` procedure (`context.rs`) — a shape-guessing heuristic that is the N≥19 fragility. Note the two things that are *not* the problem and collapse cleanly: the `*v` **borrow-return** cycle (`1 − ite + ite` → `add-sub-cancel`, linear to N=24) and **exhaustiveness** (the dead-arm cover cascades to `Inconsistent` natively). The structural fix is to emit the join as a **select** `ite(flag_0, 1, ite(flag_1, 1, …1))` instead of a sum — a heap-ternary join (see the `HeapInst::Ternary` retrofit note in the VMIR section) that folds by local rules (`ite(c,a,a)→a`, plus the opt-in `SILVER_OXIDE_PRUNE_ITE` context-pruning rules) — with an optional `Perm` role/sort so those rules fire only on permission ites. Full design in `presentation/why_switch_architecture.typ`.
- **Guarded facts across a branch** (a fact whose guard is only pc-true can't discharge an unbranched goal — see the limitation above; this, not recursion, is what blocks base-case/recursive-case heap-dep functions, and it bites heap-free code too whenever the guard isn't otherwise derivable). Tier 3.5 (`context.rs::tier35`, non-forking `ite`-goal decomposition when one branch is a constant) discharges the guarded-implication shape without a case split; a forking tier-4 case split still exists (`SILVER_OXIDE_NO_TIER4` gate) but the chosen direction moves *away* from it toward the select encoding above + a Z3 tier, not deeper case-splitting.
- **Wildcard permissions** for function preconditions (our `Snap` demands full fractional sufficiency; Silicon's default is read-access-only).

### Evaluation targets
- **Soundness**: regression tests against Silicon on handwritten benchmarks (linked lists, Fibonacci, etc.) and Prusti-generated Rust programs.
- **Performance**: end-to-end verification time, solver time, e-graph saturation metrics (node count, time to saturation, peak memory), and fallback overhead.
